# Performance baseline, 2026-11-07 14:36

The official baseline for `feat/theme-customization`, replacing [2026-11-07.md](2026-11-07.md). It holds a
manual run, comparable with the old page, and an automatic A/B run made with
[`tools/bench-home.sh`](../../tools/bench-home.sh), which later changes repeat. The measurements were taken on
2026-11-07 from 14:36 to 14:46, after a clean boot.

## Rules for every measurement

1. **Clean boot first.** Power the TV off, unplug it for 10 seconds, switch it on, and wait until it is quiet.
2. **Gate on idle CPU, not load average.** The CPU must be at least 90% idle (360% of 400%) with at most 2% I/O
   wait, in two samples 45 seconds apart (`top -d 2 -n 2`, second sample). On this Realtek board the load average
   stays near 24 on an idle TV: 22 driver threads (`hdmi_detect_tsk`, `VPQ_detect_tsk`, `DEC0_tsk`,
   `GPU_REPORT_GUAR`, ...) sleep in state D and count as load without using the CPU.
3. **Record the state:**
   - the display mode from both DisplayManager (`mActiveModeId`) and SurfaceFlinger (`refresh-rate`); the
     two number the same modes differently (60 Hz is DisplayManager mode 1 and SurfaceFlinger mode 0)
   - uptime
   - MemFree and MemAvailable, each under its own name
   - SwapFree
   - the view and window count
4. **Compare like with like.** Compare automatic runs with automatic runs (`tools/bench-home.sh`, same key script),
   and manual runs with manual runs.

## Automatic A/B (`tools/bench-home.sh`)

The script does the following:

1. Check the idle gate above.
2. Restart Home with `theme_restart.py`.
3. Warm up: 20 s on Home, open and close the App library, open and close the tile menu, back to Home, 10 s idle.
4. Record the state and PSS.
5. Reset `gfxinfo`, then press 3 rounds of 14 D-pad keys 0.4 s apart.
6. Read `gfxinfo` and PSS again.

A is the T6C theme without the `font` key (Outfit), B is the same theme with Plus Jakarta Sans.

| Metric | A, Outfit | B, Plus Jakarta Sans | B − A |
|---|---|---|---|
| TOTAL PSS after warm-up (169 views, 2 windows) | 51,499 KB | 50,460 KB | −1,039 KB |
| TOTAL PSS after the keys (123 views, 1 window) | 40,076 KB | 39,313 KB | −763 KB |
| `.ttf mmap` PSS | - | 174 KB | +174 KB |
| Total frames | 1,067 | 1,067 | 0 |
| Janky frames | 3 (0.28%) | 2 (0.19%) | −0.09 pp |
| Frame p50 / p90 / p99 | 11 / 13 / 16 ms | 11 / 13 / 15 ms | |
| GPU p50 / p90 | 7 / 9 ms | 7 / 9 ms | |
| Missed vsync / slow UI thread | 0 / 0 | 0 / 0 | |

Limits for the theme font: PSS may rise by at most 8 MB, and janky may differ by at most 2 percentage points.
**Both pass.** The PSS difference is within run-to-run noise; the font file itself costs 174 KB.

`logcat -b crash` was empty after the runs, and there were no `FATAL` lines in any buffer.

## The slow runs of 2026-11-07

Late on 2026-11-07 the same key script gave the following, for all three builds alike:

| Run | p50 | Janky | GPU p50 |
|---|---|---|---|
| Baseline APK `424672d3` | 46 ms | 18.9% | 22 ms |
| Build without a font | 46 ms | 18.7% | 22 ms |
| Build with Plus Jakarta Sans | 46 ms | 18.9% | 22 ms |

A hand run gave p50 38 ms and 13.5% janky. After a clean boot the same script and build give p50 11 ms, so the
slowness belonged to the TV's state, not to the code. Memory does not explain it. The fast hand run of the old
baseline had only 28,572 kB MemFree and about 395 MB of swap in use. The slow runs had more free memory
(`top` showed 177,180 kB MemFree at 01:07). Uptime, MemAvailable and SwapFree were not recorded for the slow
runs.

What changed is the GPU time per frame, which tripled (7-8 ms to 22 ms) while the UI thread stayed on time.
That points at the GPU or display pipeline after hours of use, many theme pushes and reinstalls; the thermal
status read 0. A long-uptime run with the rules above would confirm it.
